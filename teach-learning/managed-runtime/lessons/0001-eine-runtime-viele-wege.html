Copilot Managed Runtime · Lektion 1 · ca. 10 Minuten

Eine Runtime, viele Wege hinein

Bevor du die erste App baust, brauchst du das mentale Modell: Wer baut wo, wo läuft es, wer governt es, und wer bezahlt was.

Dein Gewinn heute: Du kannst Copilot Managed Runtime (CMR) in drei Sätzen erklären und jede Frage einer von vier Ebenen zuordnen: Bauen, Ausführen, Governen, Abrechnen.

Was CMR ist

CMR ist ein von Microsoft betriebener Host für interne Line-of-Business-Apps im Microsoft-365-Tenant. Jede App übernimmt ab dem Moment ihrer Erstellung die Governance-, Sicherheits- und Compliance-Vorgaben der Organisation.[1]

Technisch ist eine CMR-App eine TypeScript- oder JavaScript-Single-Page-App. Den Rest liefert der Host: Anmeldung über Microsoft Entra, Laden der App und Durchsetzen von Conditional Access, DLP und Sharing-Limits zur Laufzeit.[2]

Status: Public Preview seit 25.09.2026.[3] Eine Drittquelle meldet GA per Message Center MC1558033 vom 18.11.2026; das ist auf einer Microsoft-Seite noch nicht bestätigt.[4]

Vier Dinge, die Entwicklern auffallen

  • Das Git-Repo ist die Wahrheit. Builds und Deploys laufen aus echten Commits, entweder im plattformverwalteten Repo oder in deinem GitHub-Repo.[2]
  • Finger weg von ms.config.json. CLI und SDK verwalten die Datei. Änderungen laufen über ms-Befehle, sonst gerät dein lokaler Stand aus dem Takt mit der Plattform.[2]
  • Der CLI-Pfad ist ab Werk aus. Cowork und Copilot Studio sind standardmässig an. Für CLI und SDK muss ein Admin die Option erst freigeben.[5]
  • Bauen und Ausführen werden getrennt abgerechnet. Bauen zahlt das jeweilige Werkzeug. Ausführen braucht pro Person Power Apps Premium oder eine Spending Policy mit CMR, abgerechnet mit 0.1 Copilot Credits pro API-Call. Die Power-Apps-Rechte aus E3/E5 reichen nicht.[6]

Prüfe dich

Antworte aus dem Kopf, ohne hochzuscrollen. Falsche Antworten sind hier nützlich: Sie zeigen, was noch nicht sitzt.

1. Wo läuft eine App, die ein Maker in Copilot Studio gebaut hat?

Alle Baupfade erzeugen dieselbe Art von App, die im CMR-Host läuft und die Default-Governance des Tenants erbt.

2. Eine Person hat Microsoft 365 E5 und sonst keine Lizenz. Darf sie eine mit ihr geteilte App ausführen?

Die Power-Apps-Rechte aus E3/E5 gelten nicht für CMR. Nötig ist Power Apps Premium oder eine Spending Policy, die CMR einschliesst. Eine Copilot-Lizenz allein reicht ebenfalls nicht, und Teilen gibt nur Zugriff, keine Lizenz.

3. Wer sieht alle CMR-Apps des Tenants, egal mit welchem Werkzeug sie gebaut wurden?

Im Microsoft 365 Admin Center unter Apps › All apps erscheint jede App mit Owner, Abhängigkeiten, Nutzung und Health. Nutzer sehen im Portal nur die Apps, auf die sie Zugriff haben.

4. Welcher Baupfad ist im Tenant standardmässig ausgeschaltet?

CLI und SDK sind ab Werk aus und müssen vom Admin freigegeben werden. Cowork und Copilot Studio sind an, lassen sich aber einschränken.

5. Was ist laut Architektur-Doku die «Single Source of Truth» einer App?

Das Git-Repo, plattformverwaltet oder dein eigenes GitHub-Repo. ms.config.json hält nur Metadaten wie App-ID, Environment und Connectors.

6. Ein Teammitglied baut eine App in Cowork und teilt sie mit 200 Personen. Worüber wird das Ausführen abgerechnet?

Ausführen wird pro Person abgerechnet: über Power Apps Premium oder eine Spending Policy mit CMR. Eine einzelne App lässt sich in einer Policy nicht auswählen, nur Nutzer und Gruppen.

Abruf-Übung

Eine Kundin fragt: «Was ist dieses Copilot Managed Runtime?» Schreib deine Antwort in drei Sätzen, ohne hochzuscrollen. Danach vergleichst du sie mit der Musterantwort.

CMR ist ein von Microsoft betriebener Host für interne Apps im eigenen M365-Tenant. Egal ob die App in Cowork, Copilot Studio, Copilot Code oder per CLI entsteht, sie läuft mit Entra-Login und erbt von Anfang an die Governance des Tenants, und die IT sieht sie im Admin Center. Abgerechnet wird getrennt: Bauen über das Werkzeug, Ausführen pro Person über Power Apps Premium oder Copilot Credits.
